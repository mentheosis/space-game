# 0.3.2a Exterior Silhouette And Volume Lock

## Objective

Restart `prototype_shuttle` at the exterior shape level and lock the gross ship volumes before any further playable collision or interior detail work.

The previous generated blockout is useful only as proof that the Blender package, export, validation, Godot import, and evidence tooling work. It is not accepted as the design basis. This phase should create a new silhouette-driven blockout that reads correctly from side, top, front, and three-quarter views.

- `plans/0.3 roadmap to AAA/0.3.2 references/shuttle_a_exterior_front.png`

- cockpit references in the same folder for canopy, seat, and bulkhead implications only

## Design Targets

- ShuttleA-inspired compact exploration shuttle, not a copy of ShuttleA.
- Clear lower belly cargo mass.
- Raised neck/cockpit mass extending forward and above the belly.
- Large canopy volume suitable for two seats and clear pilot sightlines.
- Forward-opening belly ramp placed at the front of the belly/cargo volume, slightly aft of the cockpit nose.
- Wings/fins/engines that support the shuttle silhouette without making the hull read like a simple box.
- Scale large enough for a lower cargo deck, upper cockpit deck, side ascent path, two cockpit seats, and standing player proxies.

## Non-Goals

- Do not make playable collision the acceptance gate.
- Do not tune traversal, stair collision, or hatch interaction.
- Do not detail the cockpit interior.
- Do not spend time on final materials, lighting, decals, or decorative geometry.
- Do not integrate the new shuttle as the default gameplay ship yet.

## Process

1. Build a clean Blender scene from the reference brief.
2. Use the actual `ShuttleA.obj` as the deterministic silhouette reference, not only screenshot captures.
3. Extract reference bounds, material bounds, and normalized side/top/front envelope profiles from the OBJ.
4. Establish target proportions for length, width, height, belly height, cockpit/neck height, canopy length, ramp placement, and engine/wing stance.
5. Author exterior as simple, smooth, silhouette-first massing rather than stacked cubes.
6. Add transparent gross volume proxies for cargo deck, cockpit deck, ramp envelope, ascent envelope, seated pilot/copilot, and standing player.
7. Keep collision meshes minimal and explicitly marked as temporary export placeholders only.
8. Generate evidence that prioritizes shape: front, side, top, three-quarter, transparent volume cutaway, ramp/canopy placement review, and deterministic silhouette overlays.
9. Stop for human shape review before proceeding to interior architecture or traversal collision.

## Deterministic Shape-Fit Tool

Tooling:

- `tools/blender/analyze_prototype_shuttle_shape_fit.py`
- `scripts/analyze-prototype-shuttle-shape-fit.sh`

Outputs:

- `reports/prototype_shuttle_shape_fit/shape_fit_overlay_current.png`
- `reports/prototype_shuttle_shape_fit/shape_fit_report.json`
- `reports/prototype_shuttle_shape_fit/shape_fit_report.md`

Method:

- Read all ShuttleA OBJ vertices and transform them into the runtime ship-space coordinate system.
- Read all current prototype exterior mesh vertices from the Blender source scene.
- Normalize both meshes by ship length.
- Project both meshes into side, top, and front envelope profiles.
- Draw reference in blue and prototype in orange.
- Report mean, RMS, and max envelope deltas per projection.

This tool should become the gate for shape-lock iterations. If the overlay shows a large mismatch, do not rely on visual screenshots alone.

Implementation note:

The first generated envelope hull matched side/top numerically but lost too much front cross-section information and read as a smooth blob. The current deterministic baseline therefore uses the ShuttleA OBJ mesh itself as the exact reference blockout seed, while retaining separate prototype volume proxies for cargo/cockpit planning. This gives a zero-drift starting point before deliberate design deltas such as scale increase, belly-ramp adaptation, cargo enlargement, or canopy/cockpit redesign are applied.

Current design delta:

- Uniformly scale the ShuttleA-derived exterior seed by `1.18` around the reference center.
- Apply a modest lower-belly expansion only in the existing mid/aft belly zone.
- Preserve the ShuttleA top-view profile almost exactly while allowing a small side/front deviation for cargo volume.
- Treat the delta as provisional until human review approves the larger belly read.

## Acceptance Criteria

- Side view has an obvious lower belly cargo volume and a raised forward cockpit/neck volume.
- Top view has a swept shuttle silhouette with functional wing/fins/engine placement, not a rectangular hull.
- Front view shows enough hull width and height for a believable two-level interior.
- Canopy location and size imply a two-seat cockpit with clear forward/upward visibility.
- Belly ramp is forward on the belly/cargo mass and reads as an entry to the lower deck.
- Gross cargo and cockpit volume proxies fit inside the exterior hull.
- Standing and seated scale proxies fit within the intended volume envelopes.
- Evidence makes the exterior shape reviewable without launching the game.
- Deterministic overlay evidence shows the prototype and ShuttleA reference envelopes close enough for the deliberate design deviations we want.
- Human reviewer can answer whether the shape direction should be locked, revised, or rejected.
