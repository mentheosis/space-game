# 0.3.2e E1 Exterior Collision Audit And Contract

## Status

Started.

This document records the first exterior collision audit for the prototype
shuttle and defines the contract that should guide E2 ship-world physics work.

## Current State

The prototype shuttle currently has three different collision concepts mixed
together:

- `prototype_shuttle_collision.glb`: generated collision package used for
  walkable floors, ramp, stairs, and cockpit traversal evidence.
- runtime interaction areas in `PrototypeShuttleDebugLoader.cs`: hatch, seat,
  and interior-volume detection.
- temporary runtime underside skids in `PrototypeShuttleDebugLoader.cs`: added
  after the first playable flight test because the rigid body had no real
  platform/planet contact geometry.

The temporary skids fixed the immediate symptom but are not an acceptable
long-term answer because they were not represented in the asset package,
collision reports, or exterior review evidence.

## New Contract

The first exterior collision contract is:

`assets/source/blender/ships/prototype_shuttle/prototype_shuttle_exterior_collision_contract.json`

The contract is currently in Godot ship-local coordinates and includes named
regions for:

- `left_belly_landing_skid`
- `right_belly_landing_skid`
- `aft_belly_contact_plate`
- `forward_neck_lower_contact`

The contract labels each region by role:

- `ship_world_physics`: rigid-body contact with platform, terrain, planets, and
  large obstacles.
- future `player_walkable`: intended player traversal surfaces.
- future `interaction`: non-physical areas such as hatch, seat, exterior
  controls.

## Design Rules

1. Do not use one broad invisible hull box around the prototype shuttle.
2. Ship-world physics collision must not cross the central ramp/cargo walking
   route.
3. Player traversal collision and ship-world physics collision must be
   semantically separate, even if they eventually share exported meshes.
4. Every generated runtime collision node must use the contract region id in
   its node name.
5. Collision visibility toggled with `V` must include the contract-driven
   ship-world physics regions.
6. The temporary runtime skids should be removed as hardcoded shapes once the
   loader consumes the contract.

## E2 First-Pass Requirements

The first E2 implementation pass must:

- load the exterior collision contract;
- create named `CollisionShape3D` nodes from `ship_world_physics` regions;
- create matching visible debug boxes for the `V` overlay;
- remove the old hardcoded `AddUndersidePhysicsSkids` path;
- keep ramp, hatch, interior gravity, and pilot-seat control intact;
- pass `dotnet build` and Godot import.

## Evidence Needed Before Playtest

Before asking for manual playtest, produce or inspect:

- source contract JSON;
- generated/loaded node names in `PrototypeShuttleDebugLoader.cs`;
- Godot import output;
- `dotnet build` output.

Manual test should then verify:

- ship starts supported on the platform;
- `F` enters the prototype shuttle;
- ship-interior gravity activates inside;
- `F` sits in the cockpit;
- `Space` produces liftoff without clipping downward through the platform;
- `V` shows named collision debug support regions.
